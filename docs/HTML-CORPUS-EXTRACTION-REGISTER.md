**Revision:** 2026-10-26  
**Purpose:** Index the uploaded/generated HTML source corpus, preserve current decisions, and prevent historical drafts from silently becoming public claims.  
**Repository role:** This is an extraction and reconciliation register, not a claim that every proposal in the source corpus has been implemented. The public website is a view; the corpus remains the source of record.

## 1. Canonical resolution rules

Use this order when sources disagree:

1. Explicit user-approved constitutional canon.
2. Latest approved decision for the specific domain.
3. Latest approved domain specification.
4. Verified implementation and operational evidence.
5. Current operational register (for example, approved prices and actual availability).
6. Historical specifications and drafts.
7. Unapproved assistant synthesis or recommendation.

A newer timestamp does not overrule a constitutional invariant by itself. Keep historical values labelled as historical; do not silently rewrite them. Separate **status** (LIVE, OPERATIONAL, PROTOTYPE, RESEARCH, PROPOSED, CONCEPT, HISTORICAL, SUPERSEDED, UNKNOWN), **decision** (DRAFT, UNDER_REVIEW, ACCEPTED, REJECTED, DEFERRED, SUPERSEDED) and **evidence** (UNVERIFIED, SOURCE_SUPPORTED, REPRODUCED, TESTED, ACCEPTED, CONTESTED).
