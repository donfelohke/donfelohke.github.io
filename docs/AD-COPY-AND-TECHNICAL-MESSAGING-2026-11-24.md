## 3. Design copy and art direction

**Direction:** African Desert editorial × Ghetto-Luxe Dark Academia × Silicon Savannah neo-naturalism.

- Near-black and forest depth, ivory reading surfaces, restrained ochre/gold and terracotta accents.
- Cormorant Garamond for editorial display, Inter for body and controls, JetBrains Mono for technical metadata.
- Strong hierarchy, deliberate negative space, documentary credibility and tactile material cues.
- Text-first communication; original craft, movement and systems imagery only where provenance, rights and consent are recorded.
- Mobile-first composition, accessible contrast, keyboard visibility, reduced-motion and reduced-transparency support.

Avoid generic luxury templates, default Rasta shorthand, generic AI imagery, neon-purple HUDs, decorative code clutter and unsupported cultural symbolism.

## 4. Technical copy rules

Technical copy should identify the problem, intended user, architecture, system boundary, dependencies, versions, hardware target, security/privacy assumptions, test method, result, evidence, limitations, recovery path and maturity.

Use explicit maturity labels: **CONCEPT, RESEARCH, DOCUMENTED, CONFIGURED, BUILT, TESTED, VALIDATED, DEPLOYED, PRODUCTION-VERIFIED, UNKNOWN, BLOCKED, SUPERSEDED**.

Preferred forms:
- "This repository documents and develops..." when the work is primarily documentation or research.
- "The implementation builds..." only when a reproducible build result exists.
- "The feature passed [named test] on [target]..." only when test evidence exists.
- "Deployed" only with a named target, revision, date and rollback record.
- "Production-verified" only with operational history, monitoring, acceptance evidence and tested recovery.

Never convert an inventory, architecture diagram, proposed bill of materials or repository file into a claim of implementation or customer availability.
