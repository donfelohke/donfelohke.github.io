# Contributing

1. Read README.md, AGENTS.md, GOVERNANCE.md and relevant docs.
2. Create a descriptive branch; keep changes focused.
3. Explain the user need, outcome and acceptance criteria.
4. Run HTML checks and inspect visual changes on mobile and desktop.
5. Open a pull request with summary, tests, screenshots where relevant, risks and limitations.
6. Address review comments before merge.

Do not invent facts, testimonials, service guarantees, prices or deployment status. Keep the site accessible and dependency-light. Never commit secrets or private customer data. Preserve the repository's existing GPL-3.0 LICENSE. Use concise imperative commit messages.
